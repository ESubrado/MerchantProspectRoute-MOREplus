# Backend gap register

## Scope and interpretation

This register compares the requested standalone scope with the checked-in source at `af98b0aade26394a80395b1ff81c29d22a375fd9`. A source UI, query, generated type, RPC call or Edge Function invocation is not a backend implementation. No missing item below will be satisfied by connecting the new project to the source repository or its services.

| ID | Severity | Gap / evidence | Impact on target | Required target decision or implementation |
| --- | --- | --- | --- | --- |
| BG-01 | Blocker | No migrations, SQL schema, indexes, RLS policies, triggers or seed data are present. `lib/database.types.ts` is the sole schema artifact. | No independently deployable data layer; constraints and access behavior cannot be reproduced safely. | Design/version the target schema, indexes, migrations, tenant authorization, constraints and test fixtures. |
| BG-02 | Blocker | The source directly invokes ten RPCs, but no bodies/grants/transactions are checked in. | Search, canonical-email creation, mailbox threshold, sequence lifecycle and routing commands have no backend behavior. | Implement each needed command as project-owned database transactions/services; do not infer SQL solely from names. |

## Assumptions to validate before implementation

| ID | Assumption made for target architecture | Why it is not established by source |
| --- | --- | --- |
| A-01 | Every CRM/outreach record is workspace-scoped and workspace membership gates access. | Source queries and comments imply this; actual foreign keys/RLS are unavailable. |
| A-02 | A lead may have many contact methods, one current assignee, many followers, and at most one current mailbox route. | UI and relation names imply this; DDL/cardinality is unavailable. |
| A-03 | DNC is a compliance control that prevents future cold sends; DNC/reply/bounce stop active enrollment. | The source names states and comments, but no state machine is present. |
| A-04 | Sequence sending needs a durable queue and idempotent provider submission. | Generated queue RPC signatures imply it, while implementation is absent. |
| A-05 | Mailbox identity is external-provider-owned and the stored `emailengine_account` is not a target domain identifier to retain. | The source is specific to EmailEngine; target provider has not been selected. |
| A-06 | Mailbox health can be separate from sending policy; an explicit send pause takes precedence over threshold automation. | The UI shows both flags but no precedence logic. |
| A-07 | CSV imports can safely resume from committed batch checkpoints and report source-compatible counters. | Client retry comments imply this, but job/worker transaction semantics are absent. |
| A-08 | Only conversations with inbound mail appear in the general inbox, whereas a lead execution panel retains outbound sequence history. | This is explicit source UI/query behavior and is adopted as a product assumption, not an industry default. |
| A-09 | Search must be tenant-scoped before ranking and must support contact/company identity fields. | Source RPC comments indicate an RLS/performance issue; source has no index definition. |
| A-10 | The standalone project may choose a different database, queue, storage service and email provider as long as it owns the integrations. | The user prohibited runtime dependencies on SOURCE; no target infrastructure choice was provided. |

## Backend work that is demonstrably present only as a contract

These items should be considered requirements to design, not source implementations to extract:

- Direct RPC contracts: `find_or_create_email_address`, `search_lead_ids`, `search_company_ids`, `set_deliverability_threshold`, `set_sequence_status`, `reorder_sequence_steps`, `start_lead_sequence`, `stop_lead_sequence`, `resume_lead_sequence`, `reassign_lead_email_route`.
- Types-only worker contracts: `claim_sequence_dispatch`, `complete_sequence_dispatch`, `fail_sequence_dispatch`, `sequence_queue_read`, `get_sequence_queue_metrics`, `process_lead_import_rows`, and `apply_warmy_health`.
- Edge Function contracts: `process-lead-import`, `send-message`; `create-staff-member` is excluded from the target feature scope.
- Remote conventions relied on by source comments: phone/social normalization triggers, company uniqueness, contact access, mailbox health automation, import-job authorization, and attachment Storage RLS.

No application code has been scaffolded while these decisions remain documented as gaps rather than silently assumed implementations.
